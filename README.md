# MoviePick (RandomMovie)

Веб-приложение для подбора фильмов по пользовательским критериям (жанр, год, рейтинг, страна, длительность) с возможностью случайного выбора и сохранения фильмов в избранное. Данные о фильмах получаются через внешний REST API [The Movie Database (TMDB)](https://www.themoviedb.org/documentation/api).

## Технологии

HTML5, CSS3, JavaScript (ES6+), Bootstrap 5, Animate.css, Font Awesome. Хранение избранного реализовано на стороне клиента через LocalStorage браузера, отдельного бэкенда у приложения нет.

### IDEF0 — функциональное моделирование

Функциональная модель показывает систему как совокупность процессов с их входами, выходами, управлением и механизмами.

**Контекстная диаграмма (A0)** — верхнеуровневое представление системы: на вход поступают запрос пользователя и критерии поиска, на выходе — список фильмов, карточка выбранного фильма, список избранного и уведомления об ошибках.

![IDEF0 Context](./idef0_context_A0.png)

**Декомпозиция первого уровня** — раскрывает A0 на четыре процесса: обработка пользовательских запросов, формирование и отправка запросов к TMDB API, управление списком избранных фильмов, обработка и визуализация данных.

![IDEF0 Decomposition](./idef0_decomposition_A0.png)

### IDEF3 — процессное моделирование

Описывает последовательность выполнения процессов во времени, с ветвлениями через логические операторы (AND/OR/XOR).

**Верхнеуровневый процесс** — от инициации сессии пользователя до отображения результата, включая обработку ошибок и retry-логику при неудачном запросе к TMDB.

![IDEF3 Process](./idef3_process_top.png)

**Декомпозиция блока "Получение и нормализация результатов"** — парсинг JSON-ответа от TMDB, проверка структуры данных, извлечение и преобразование в формат приложения, проверка на пустой результат.

![IDEF3 Decomposition B4](./idef3_decomposition_B4.png)

**Декомпозиция блока "Управление избранным"** — логика добавления/удаления фильма из избранного, включая проверку на дублирование записей.

### UML — проектирование архитектуры

**Диаграмма прецедентов (Use Case)** — сценарии взаимодействия пользователя с системой: поиск и фильтрация фильмов, случайный выбор, управление избранным, а также взаимодействие системы с внешним TMDB API.

![UML Use Case](./uml_use_case.png)

**Диаграмма классов (Class Diagram)** — структура классов приложения: `UserInterface`, `FilterParameters`, `APIClient`, `Movie`, `MovieCollection`, `DetailedMovie`, `FavoriteMovie`, `Genre` — с их атрибутами, методами и связями (агрегация, композиция, наследование).

![UML Class Diagram](./uml_class_diagram.png)

**Диаграмма последовательности (Sequence Diagram)** — сценарий запроса фильмов по критериям, обработки успешного и ошибочного ответа от API, а также добавления фильма в избранное.

**Диаграмма состояний (State Machine)** — жизненный цикл фильма в контексте избранного: от "не существует" до "создан" → "сохранён в хранилище" → "удалён".

![UML State Machine](./uml_state_machine.png)

### BPMN — процесс подбора фильма

Диаграмма в нотации BPMN показывает процесс "как есть" с точки зрения бизнес-процесса, с разделением по дорожкам (swimlanes) между участниками: пользователь, интерфейс приложения, внешний TMDB API и локальное хранилище браузера. В отличие от IDEF3, BPMN явно показывает, кто именно выполняет каждый шаг, и удобнее для описания взаимодействия между системой и внешними участниками.

![BPMN Diagram](./bpmn_movie_selection.svg)

## Структура данных

- **Фильм**: ID, название, оригинальное название, описание, постер (URL), рейтинг, дата выхода, жанры, страна производства, длительность
- **Избранное**: массив ID фильмов с основными атрибутами, хранится в LocalStorage
- **Параметры поиска**: жанр, год, страна, рейтинг, длительность, способ сортировки

## Требования к качеству (кратко)

- Время отклика — не более 4 секунд при загрузке фильма
- Стабильная работа при 100 одновременных запросах
- Уровень доступности — не менее 95%
- Адаптивный интерфейс для всех типов экранов
- Работа без регистрации пользователей

Полный список функциональных и нефункциональных требований — в [SRS.md](./SRS.md).
