# Software Requirements Specification — АС «MoviePick»

Документ составлен на основе технического задания по ГОСТ 34.602-2020, разработанного в рамках курсовой работы по дисциплине «Технология разработки программного обеспечения и оценка качества».

## 1. Назначение системы

АС «MoviePick» предназначена для подбора фильмов по критериям, задаваемым пользователем, с возможностью просмотра описания, рейтинга и добавления понравившихся фильмов в избранное. Приложение использует данные с сервиса The Movie Database (TMDB) через открытое REST API.

## 2. Цели создания системы

1. Повысить удобство выбора фильмов пользователем за счёт персонализированного подбора.
2. Сократить время, затрачиваемое на поиск интересного контента.
3. Повысить точность рекомендаций за счёт фильтрации по параметрам: жанр, рейтинг, год, длительность и страна.
4. Обеспечить современный, отзывчивый и эстетичный интерфейс.

## 3. Функциональные требования (подсистемы)

### 3.1 Подсистема взаимодействия с пользователем
Веб-интерфейс с формами ввода параметров, кнопками управления, модальными окнами и панелью просмотра результатов. Адаптивный дизайн, поддержка тёмной темы.

### 3.2 Подсистема фильтрации и формирования поисковых запросов
Обработка параметров, задаваемых пользователем (жанр, страна, год выпуска, рейтинг, длительность, сортировка). Формирование структурированных запросов к TMDB API. Поддержка комбинирования нескольких фильтров.

### 3.3 Подсистема обработки и отображения данных
Получение результатов от TMDB, преобразование во внутренний формат. Отбор и форматирование информации о фильме: название, жанры, постер, описание, рейтинг, дата выхода. Формат данных совместим с REST API и JSON.

### 3.4 Подсистема выбора и генерации рекомендаций
Подбор фильма на основе выбранных фильтров или случайный выбор без ограничений. Результат отображается в модальном окне с возможностью повторного выбора.

### 3.5 Подсистема управления списком избранных фильмов
Сохранение и отображение фильмов, добавленных в избранное. Хранение — локально на стороне клиента (LocalStorage). Операции: добавление, удаление, просмотр.

### 3.6 Подсистема конфигурации и администрирования
Параметры конфигурации приложения: ключи доступа к TMDB API, настройки интерфейса. Изменение настроек без вмешательства в основной код.

## 4. Нефункциональные требования

### 4.1 Требования к надёжности
- Корректная обработка ошибок при взаимодействии с внешним API (отсутствие соединения, неверный ответ)
- При недоступности TMDB API — информативное сообщение пользователю
- Локальный функционал (просмотр избранного) должен оставаться доступным независимо от состояния API
- Время отклика — не более 4 секунд при загрузке фильма
- Стабильная работа при 100 одновременных запросах
- Уровень доступности — не менее 95%

### 4.2 Требования к интерфейсу
- Адаптивность для всех типов экранов (ПК, ноутбуки, планшеты, смартфоны)
- Поддержка современных браузеров (Chrome, Firefox, Safari, Yandex) с HTML5, CSS3, ES6+
- Работа без регистрации пользователей

### 4.3 Требования к информационному обеспечению
Основной массив данных предоставляется TMDB API в реальном времени, на клиенте не хранится. Пользовательские данные (избранное) — LocalStorage браузера.

### 4.4 Требования к взаимодействию компонентов
- Передача данных по протоколу HTTPS
- Обмен с внешними сервисами — REST API, формат JSON
- Возможность расширения и интеграции с другими API-сервисами

## 5. Условия эксплуатации

- Устройства: стационарные ПК, ноутбуки, планшеты, смартфоны
- ОС: Windows 10/11, macOS, Android, iOS
- Необходим постоянный доступ к интернету

## 6. Перспективы развития

1. Внедрение алгоритмов персональных рекомендаций
2. Система пользовательских оценок и комментариев
3. Мобильное приложение на основе существующего интерфейса
4. Расширенный фильтр поиска (по актёрам, языку, настроению, ключевым словам)
